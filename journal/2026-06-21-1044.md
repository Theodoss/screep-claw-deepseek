# Screeps Journal - 2026-06-21 10:44 EDT

## 發現問題
- economyMode 卡在 `rcl2-recovery`，upgradeRate = 0，upgraderWorkTarget = 0
- 4 個 rcl1Upgrader 全在做 `transfer:extension` 而非升級 controller
- storedEnergy 64K、energyAvailable 滿格，但系統判斷 recovery

## 根因
source `dbc41b` 無 miner（minerName: null），只有 `dbc41c` 有 miner。
`rcl2ContainerEconomy.findSourceWithoutMiner()` 回傳 missing → `minersHealthy = false`
→ `economy.update()` recovery 條件中 `minersHealthy === false` **無能量門檻**，
直接觸發 recovery → upgradeRate 歸零。

對比 `haulersHealthy` 有 `storedEnergy < 5000` 門檻，但 `minersHealthy` 沒有。

## 改動
**manager.economy.js** — recovery 條件加上能量門檻：
```diff
- input.minersHealthy === false ||
+ (input.minersHealthy === false && storedEnergy < 5000) ||
```

單一 source 缺 miner + 64K 能量 ≠ 緊急狀態，不該鎖死升級。

## 預期效果
- recovery 立即退出（minersHealthy=false 但 storedEnergy 64K > 5000）
- upgradeRate 恢復正常 (> 0)
- upgrader 開始升級 controller
- spawn queue 正常產出缺失的 rcl2Miner

## 下輪驗收
- economyMode 不再是 recovery
- upgradeRate > 0
- controller 進度有推進
- rcl2Miner count 從 1 → 2
