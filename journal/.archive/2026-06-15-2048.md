## 本輪改動 — isHomeEconomyStable 放寬能量要求

### 問題
`manager.remote.js` 的 `isHomeEconomyStable()` 原本要求
`room.energyAvailable >= room.energyCapacityAvailable`（所有 extension 必須滿）
才允許遠程 spawn。但當 storedEnergy 高達 376k 時，一個 150-energy 的瞬時缺口
只是噪音，不構成穩定性威脅。這個過度保守的檢查導致遠程 creep 替補不穩定，
尤其在 RCL5 過渡期 spawn 活動增加的期間。

### 改動
在 `isHomeEconomyStable()` 中，當 `storedEnergy >= 50000` 時跳過
`energyAvailable >= energyCapacityAvailable` 檢查。
其他所有條件（spawn 存活、無敵對、container economy ready、無 recovery 等）保持不變。

```diff
   const spawn = getHomeSpawn(room);
   if (!spawn || spawn.spawning) return false;
+
+  // When stored energy is abundant (>50k), transient extension dips
+  // should not pause remote spawning.
+  const remoteRoomMemory = Memory.rooms && Memory.rooms[homeRoomName]
+    ? Memory.rooms[homeRoomName] : {};
+  const remoteEconMemory = remoteRoomMemory.economyAccounting || {};
+  const storedEnergy = remoteEconMemory.storedEnergy || 0;
+  if (storedEnergy < 50000 && room.energyAvailable < room.energyCapacityAvailable) {
+    return false;
+  }
+
-  if (room.energyAvailable < room.energyCapacityAvailable) return false;
```

### 預期效果
- 遠程 creep 替補不再因 transient extension dips 中斷
- RCL5 過渡期 spawn 活動增加時，遠程 energy flow 保持連續
- 安全性不降：其他 10+ 條件（spawn、敵對、economy ready、container 等）保持不變
- storedEnergy < 50k 時行為與原版完全相同
