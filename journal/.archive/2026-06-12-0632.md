# Screeps Journal - 2026-06-12 06:32 UTC (Hotfix)

## Hotfix

**發現**: 大部分的 hauler 不會動，因為 upgrader 不從 controller 附近的 container 取能量。

## 問題分析

**成因**: RCL2 之後有兩個獨立的問題：

1. **Hauler 沒地方卸貨** → 兩個 container 各 2000 能量全滿，spawn 滿載
   550/550，又沒有 controller container → `findEnergyTarget()` 永遠回傳 null，
   haulers 滿能量卡在原地。

2. **Upgrader 自己跑去 source 挖礦** → 不用 container 的能量，浪費 source
   slots 跟移動時間。每趟從 controller 走到 source B 來回至少 30+ ticks。

**結果**: 兩台 hauler 不動、能量全部積壓在 source containers、upgrader 效率低落。

## 改動

### `manager.rcl2ContainerEconomy.js`
- 新增 `discoverControllerContainer()` — 每 100 ticks 檢查 controller 附近
  是否已有 container；沒有就在 controller 相鄰格子找空地放 construction site。
- 邏輯跟 source container 自動擺放一致。

### `role.rcl1Upgrader.js`
- 新增 `getControllerContainer()` — 檢查 controller 範圍 3 內的非 source container（有能量的）
- `working=false` 時：**先從 controller container 取能量**，沒有的話才回退去 source 挖礦
- `working=true` 時：沿用 `support.runPriorityWork()`（fill spawn → build → fill extension → upgrade）

## 預期效果

1. Controller container 在 ~60 ticks（1 builder WORK）內建好
2. 之後 haulers 會把多餘能量 dump 到 controller container
3. Upgraders 從 controller container 取能量 → 省下走回 source 的時間
4. 整體升級效率提升（更短往返時間、不用跟 miner 搶 source slots）
