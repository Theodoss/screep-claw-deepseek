## 上輪對照

上輪改了 `manager.rcl2ContainerEconomy.js` 加入 `placeContainerSites()`。

**預期**: container construction site 會被自動建立。
**實際**: 有 3 個 construction sites (包含容器)，但 `suggestedContainerPos: null` 導致 `placeContainerSites()` 永遠不執行。容器也未建造。

## 診斷問題

**根因**: 4 台 rcl1Harvester 佔滿所有 4 個採集點 (source b 有 3 個點、source c 有 1 個點)，builder 和 upgrader 無法取得能量。Builder 沒能量 → 無法建造容器 → 經濟卡在 rcl1-bootstrap。

**次要問題**: `placeContainerSites()` 依賴 `suggestedContainerPos`，但此欄位在上次成功建立 construction site 後被設為 null，導致無法再次觸發建立。

## 本輪改動

只做了**一個重點改動**+一個防禦性補強：

### 1. `manager.rcl1Bootstrap.js` — 保留 1 個採集點
```javascript
// 修改前
const normalHarvesterTarget = Math.min(totalSlots, 4);
// 修改後
const normalHarvesterTarget = Math.min(Math.max(1, totalSlots - 1), 4);
```
效果: 4 個採集點時只產 3 台 harvester，留 1 個點給 builder/upgrader 採集能量。最低保證 1 台 harvester 不讓殖民地崩潰。

### 2. `manager.rcl2ContainerEconomy.js` — 防禦性 fallback
```javascript
// 修改前
if (!entry.suggestedContainerPos) continue;
const pos = entry.suggestedContainerPos;
// 修改後
const pos = entry.suggestedContainerPos || entry.plannedContainerPos;
if (!pos) continue;
```
在 `suggestedContainerPos` 為 null 時 fallback 到 `plannedContainerPos`，確保容器站點能被建立。
