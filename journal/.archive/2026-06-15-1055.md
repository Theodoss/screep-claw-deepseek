## 本輪瓶頸 — Remote Hauler 卡住不送貨

### 問題
`delivering` flag 只在 `freeCapacity===0`（100% 滿）和 `usedCapacity===0`（0% 空）時切換。
Remote haulers 從 container 取貨時，若 container 空了但 hauler 還沒滿：
- hauler 530/650 → free=120 → `delivering` 依然是 false
- hauler 610/650 → free=40 → `delivering` 依然是 false
→ 永遠卡在 `collect()` 模式，在空的 container 旁邊發呆

本輪實際觀察：remoteHauler-71690483 (530/650) 和 remoteHauler-71690561 (610/650) 卡在 W49N26，task=null。

### 改動
`role.remoteHauler.js` — delivering 判定加入閾值：
```diff
- if (creep.store.getFreeCapacity(RESOURCE_ENERGY) === 0) {
-     creep.memory.delivering = true;
- }
- if (creep.store.getUsedCapacity(RESOURCE_ENERGY) === 0) {
-     creep.memory.delivering = false;
- }
+ const used = creep.store.getUsedCapacity(RESOURCE_ENERGY);
+ const free = creep.store.getFreeCapacity(RESOURCE_ENERGY);
+ const cap = creep.store.getCapacity(RESOURCE_ENERGY);
+
+ if (free === 0 || (used > 0 && cap > 0 && free / cap < 0.2)) {
+     creep.memory.delivering = true;  // 完全滿 或 80%+ 滿 → 送貨
+ }
+ if (used === 0 || (creep.memory.delivering && cap > 0 && used / cap < 0.1)) {
+     creep.memory.delivering = false; // 完全空 或 正在送但 <10% 剩餘 → 取貨
+ }
```

邏輯：
- 滿度 ≥80% → 送貨（不再等到 100%）
- 若已決定送貨，退回 <10% → 取貨（防止震盪）
- 完全滿/完全空仍如舊觸發
