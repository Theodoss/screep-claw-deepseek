## 🪲 發現：Upgraders 卡在 storage 長途跋涉

3/4 個 upgraders 顯示 `task:withdraw:storage-fallback`，energy=0：
- controller container 被 48 WORK upgraders 高速抽乾（48 energy/tick）
- 退路順序：controller container → **storage** → spawn/extension
- storage 距離 controller 很遠（通常在房間另一端）
- upgraders 花大量 tick 走路而非升級 → upgradeRate 從 84 掉至 75

## 本輪改動

**role.rcl1Upgrader.js**: 調換能量提取優先級。原有順序：
controller container → storage → spawn/extension
改為：
controller container → **spawn/extension → storage**

spawn/extension 通常緊鄰 controller container，距離極短。當 controller
container 被抽乾時，upgraders 直接從旁邊的 extension 取能量，而非
跋涉到遠方的 storage。這可大幅減少 upgrader 空轉時間。
