## 發現的瓶頸：Upgrader 控制器容器空載停擺

### 根因
`role.rcl1Upgrader.js` 的取能邏輯：
1. 有 controller container → **只從 controller container 取**
2. controller container 空 → `idle:controller-container-empty` → **直接 return，不做任何事**
3. 沒有 controller container → `idle:no-controller-container` → **也直接 return**
4. 唯一的 fallback 是 recovery/RCL<2 → 直接 harvest source

這導致：當 controller container 因任何原因空了（hauler 優先補 spawn→tower→storage），upgrader 完全不工作。即使 storage 有 82k 能量。

### 改動（role.rcl1Upgrader.js）

**單一改動：Upgrader 取能 fallback 鏈**

```
1. Controller container（優先，有能量時）
2. Storage（fallback #1，當 container 空或不存在）
3. Spawn/Extension（fallback #2，最後手段）
4. idle:no-energy-source（真沒能量時才閒置）
```

**邏輯**：
- 合併 container 空的檢查進條件：只在 container 有能量時才 withdraw
- 新增 storage fallback：RCL ≥ 2 且 container 空 → 從 storage 取能
- 新增 spawn/extension fallback：storage 也空 → 從 spawn/ext 取能
- 全部空 → 標記 `idle:no-energy-source`（真正無能量）

### 預期效果
- 當下：idle upgrader 立即恢復工作（storage 有 82k 能量）
- 實際 upgrade 從 ~1/tick → ~2/tick（仍受 small body 1 WORK 限制）
- storedEnergy 增長放緩（能量轉向升級）
- 長期：即使 controller container 維護不佳，upgrader 也不會停擺

### 下輪驗收
- 無 `idle:controller-container-empty` task
- 兩台 upgrader 都應 working=true
- upgradeCredits 開始消耗（不再是堆積狀態）
- 若 controller container 重新有能量 → upgrader 自動回到高效的 container 路徑
