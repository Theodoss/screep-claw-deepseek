# Screeps Journal - 2026-06-16 17:24 EDT

## 使用者要求
三 remote 共 6 個額外資源應加入經濟計算（population plan、income rate）

## 診斷
三個環節都沒納入 remote 數據：

1. **Remote 能量未計入 income rate**：`role.remoteHauler.js` 送能量回主房時沒有呼叫 `economy.recordHarvest()`，導致 economy accounting 的 `incomeRate` 完全看不到 remote energy → upgrade 預算被低估。

2. **Population plan 不認 remote creep**：`manager.rcl2ContainerEconomy.js` 兩次呼叫 `population.getPlan()` 都沒傳 `remoteRoomCount` / `remoteSourceCount`，導致所有 remote creep target 為 0。

3. **Stats 報表同上**：`manager.stats.js` 的 fallback plan 也沒傳 remote counts。

## 改動
- **`role.remoteHauler.js`**：deliver 到主房時呼叫 `economy.recordHarvest(homeRoom, carried)`，remote 能量納入 income 計算
- **`manager.rcl2ContainerEconomy.js`**：從 `Memory.remote[room.name].rooms` 統計 active remote room/source 數，傳入兩次 `population.getPlan()`
- **`manager.stats.js`**：同上，fallback plan 也納入 remote counts

## 預期效果
- W49N25 population plan 顯示: remoteMiner target=6, remoteHauler target=6, reserver target=3
- Remote hauler 每次送貨回家都記錄 harvesting → incomeRate 上升 → upgradeRate 上升 → 更多 upgrader
- Stats 報表正確反映 remote program 規模
- 實際 spawning 仍由 `manager.remote.js::getSpawnRequests()` 獨立控制，不受影響
