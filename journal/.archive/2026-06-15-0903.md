## 本輪改動 — Reserver 替補：已存在 reserver 時跳過 reservationLow

### 問題
`getSpawnRequests()` reserver spawn 條件：
```js
reservationLow && hasHealthyAssignedCreep(...)
```
`reservationLow` = `controller.reservation.ticksToEnd < 2000`。
現有 reserver 正活躍維持 → ticksToEnd 高 → `reservationLow` = false → 即使 reserver TTL=11 也不生替補。

reserver 死後 reservation 遞減，需等 ~1500 ticks 降到 <2000 才觸發替補 → 長時間真空期。

### 改動
`manager.remote.js` L741-749：reserver spawn 條件從：
```diff
- reservationLow &&
  !hasHealthyAssignedCreep(reservers, reserverReplacementLead)
+ !hasHealthyAssignedCreep(reservers, reserverReplacementLead) &&
+ (reservationLow || reservers.length > 0)
```

邏輯：
- **第一個 reserver**：仍需 `reservationLow`（沒必要 reserve 就不 spawn）
- **已有 reserver 但快死**：純依 TTL 判斷，無視 reservationLow → 不會有真空期

### 預期效果
- 現有 reserver（TTL=11）下一 tick 立即觸發替補請求
- 新 reserver 在舊的死亡後 ~150 ticks 抵達 W49N26（156 lead time）
- 之後所有 reserver 都會在 TTL 不足時自動預替換，reservation 不中斷
