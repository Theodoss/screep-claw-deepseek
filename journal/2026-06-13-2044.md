## 🔴 重大發現：RCL4 過渡崩潰 bug

`manager.economy.js` 第 243 行 `recovery = false` 對 `const recovery` 賦值導致
`TypeError: Assignment to constant variable`（91 次記錄，tick 71647625-71647715）。

錯誤停止的唯一原因是 `isPreparingAttack()` 檢查 `controller.level < 4` 時返回 false
（當前 RCL3）。但 controller 進度 134,358/135,000 — **RCL4 即將達成**。

**若未修復，RCL4 一到就會每 tick 拋錯，導致 `rcl2ContainerEconomy.run` 崩潰，
強制進入 bootstrap fallback，殖民地實質崩盤。**

## 改動
**manager.economy.js — 修復 attack prep crash + hostiles guard**

1. `const recovery` → `let recovery`（防止 const 賦值 crash）
2. `if (isPreparingAttack(room))` → `if (input.hostilesCount > 0 && isPreparingAttack(room))`
   - 殖民地 0 hostile，attack prep 無必要。若啟動會 set upgradeRate=1, 浪費經濟。
