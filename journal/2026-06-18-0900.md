## Creep 狀態分析

### 🪲 上輪修復連鎖問題
上輪修復（body builder 改用 energyAvailable）導致連鎖劣化：

1. **修復生效後**：spawn 在能量低谷時生出了極小的 upgrader
   （[WORK, CARRY, MOVE] 僅 1 WORK part），因為 energyAvailable 太低
2. **數量陷阱**：4 個小 upgraders 填滿了 count limit=4
3. **升級鎖死**：`(count - dying) < limit` 條件為 false → 不能再生新的
4. **總 work 只有 4**，遠低於 target 35 → 升級速度暴跌

## 本輪改動

**manager.rcl1Bootstrap.js**: 放寬 upgrader spawn 條件。除了原有
`(count-dying) < limit` 之外，新增 OR 條件：
`healthyWork < upgraderWorkTarget * 0.25`（總 work < 目標的 25%）。
這允許在現有 upgraders 嚴重不足時（如全都是基本 body），即使 count=limit
也能多生一隻大 body upgrader。
