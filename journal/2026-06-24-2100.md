## 🔴 發現：W49N25 upgraders 再度 stuck

15:00 修復了 link withdraw 的 race condition，但 **upgrade container withdraw 有相同 bug**：

兩隻 upgrader 都卡在 `withdraw:upgrade-container, e=0/50, work=False`。
Container 在 check 時有 energy，但 `withdraw()` 前被 haulers transfer 走（或 link→container fill），
代碼無論 withdraw 成功與否都 `return`，fallthrough 完全被 block。

這是與 15:00 link withdraw 完全相同的 race condition pattern，只是發生在 upgrade container。

## 改動：upgrade container withdraw fallthrough（same fix as 15:00）

`role.upgrader.js` upgrade container withdraw：與 15:00 link fix 相同——
`return` 只在 `ERR_NOT_IN_RANGE`（移動中）或實際取得能量（`getUsedCapacity > 0`）時呼叫。
Container 被 drain 導致 withdraw 失敗時 fall through 到 spawn/ext/storage。

```diff
-        return;  // unconditional — even when withdraw fails
+        if (result === ERR_NOT_IN_RANGE) { ... return; }
+        if (creep.store.getUsedCapacity(RESOURCE_ENERGY) > 0) { return; }
```
