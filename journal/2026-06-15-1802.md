## 本輪改動 — Upgrader 替補：排除 dying 後判斷 count

### 問題
`bootstrap.run()` 的 upgrader spawn 條件：
```js
upgraders.count < upgraderPolicy.limit + 1  // count=3, limit=2 → 3<3 = false
```
`getUpgraderState()` 的 `count` 包含**所有** upgrader（包括即將死亡的）。
目前 rcl1Upgrader-71696951 (TTL=64) 快死了，WORK=7，不在 healthyWork 中。
但 `count=3 ≥ 3` 導致條件失敗 → 無法觸發替補 → 等 64 ticks 死後才 spawn。

這造成 ~80 tick 的升級真空期（64 死亡等待 + 3 spawn + ~10 移動），
upgraderWork 從 17 驟降到 10 → upgradeRate 暫降 → 延遲 RCL5 ~6 分鐘。

### 改動
1. `getUpgraderState()` 加入 `dyingCount` 追蹤：
```diff
+ let dyingCount = 0;
  ...
+ } else {
+   dyingCount++;
  }
  return {
    count, healthyWork,
+   dyingCount
  };
```

2. `bootstrap.run()` spawn 條件改用 `count - dyingCount`：
```diff
- upgraders.count < upgraderPolicy.limit + 1
+ (upgraders.count - upgraders.dyingCount) < upgraderPolicy.limit + 1
```

邏輯：排除即將死亡的 upgrader 後的 count（healthyCount）來判斷是否需要 spawn。
目前：count=3, dyingCount=1 → healthyCount=2 < 3 → **觸發替補** ✅
