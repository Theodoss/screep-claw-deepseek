## 本輪決定：Guard 駐守策略

**根因分析**：W48N25 反覆被 wipe 的循環 ——
1. NPC 入侵 → 經濟 creep 全滅
2. Guard 從 W49N25 出發（旅行時間約 50 ticks）
3. Guard 到達、清除威脅、**返航回家**
4. 經濟 creep 返回重建（花費大量 spawn 能量）
5. NPC 再次入侵 → goto 1

**關鍵漏洞**：Guard 清除威脅後立即返航，導致房間再次門戶大開。

**改動**：`role.remoteGuard.js` — Guard 清除威脅後**留在目標房間駐守**，而非返航。
只有在 TTL < 300（即將死亡）時才回家等待替換。

**改前**：
```js
// Threat cleared — return home and standby
if (moveToRoom(creep, homeRoom)) {
    creep.memory.task = 'returning:home';
    return;
}
creep.memory.task = 'standby:home';
```

**改後**：
```js
// Threat cleared — garrison the remote room to block the next invasion.
if (creep.ticksToLive < 300) {
    if (moveToRoom(creep, homeRoom)) {
        creep.memory.task = 'returning:home';
        return;
    }
}
if (targetRoom && creep.pos.roomName !== targetRoom) {
    if (moveToRoom(creep, targetRoom)) {
        creep.memory.task = 'garrison:' + targetRoom;
        return;
    }
}
creep.memory.task = 'garrison:' + (targetRoom || homeRoom);
```

**效果**：
- W48N25（目前 guard TTL 1170，正在該房間）→ guard 會留在 W48N25 駐守
- W49N26（目前 guard TTL 326）→ TTL 低，仍會回家，但下次會駐守
- 駐守 guard 會在入侵瞬間立即交戰（零旅行延遲），保護經濟 creep
- MAX_GUARDS_PER_ROOM=1 確保不會重複派遣

**預期效果**：
- W48N25 不再反覆被 wipe（guard 已駐守，下次入侵會立刻迎戰）
- 重建能量消耗大幅降低（無需反覆重建經濟 creep）
- storedEnergy 和 incomeRate 快速回升
