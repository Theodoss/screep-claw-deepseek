## 🚨 根因：大 upgrader 飢餓循環

### 發生鏈
1. 06:00 bodyPolicy 在 energyAvailable=2300 時產生 [W×17,C×2,M×10]（2300e）
2. 單次 spawn 耗盡全部能量 → energyAvailable 歸零
3. Remote 程式（優先執行）在 energyAvailable=0 時無法 spawn remote miner/hauler
4. Remote minter/hauler 老死後無替補 → W48N25 遠端經濟死亡
5. W48N25 的 2 sources × 10e/tick = **20e/tick 消失**（佔總收入 33%）
6. 收入銳減但 upgrader 消費不減 → storedEnergy 加速崩跌

### 證據
- W48N25 在 09:00 有 7 creeps（含 miners+haulers），12:00 僅剩 1 guard
- W48N25 容器全滿（2000+1210）但無人採集 — 產能閒置
- remoteMiner count=0（全部 remote 0 miners！但 W48N26/W49N26 有 miners，所以是 W49N25 的 population 追蹤有問題... 但 W48N25 確實沒 miner）
- storedEnergy 從 41,721 → 22,933（3h 蒸發 45%）
- 1000-tick 能量率 -3,348（自由落體）

## 本輪決定：限制 upgrader body 成本上限 = 50% capacity

**改動**：`manager.rcl2ContainerEconomy.js` — upgraderBodyBuilder 將能量預算上限設為 `room.energyCapacityAvailable × 0.5`（floor=300）。

**效果**：
- W49N25 capacity=2300 → 上限 1150 → body [W×8,C×2,M×5] = 1150e
- 單次 spawn 只消耗 50% 能量，剩餘 1150e 供 remote 程式 spawn
- 4 upgraders × 8 WORK = 32 WORK（從峰值 48 下調，但仍比 basic body 強 8 倍）
- 32 WORK demand（~22e/tick）vs 3 haulers supply（~60e/tick）→ 健康盈餘

**取捨**：犧牲部分 upgrade 速度來拯救 W48N25 遠端經濟。失去 20e/tick 遠端收入比降低 upgrader 身體規格更致命。
