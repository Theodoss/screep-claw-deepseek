## 🔴 關鍵發現：W49N25 upgraders 雙雙 stuck

兩隻 upgrader 都卡在 `task=withdraw:upgrader-link, e=0/100, work=False`。
upgraderLink 是空的 — link manager 可能在每個 tick 把 energy 轉走，
比 upgrader 嘗試 withdraw 更快。

### 根因
`role.upgrader.js` link withdraw 區塊：**`>0` check 和 `withdraw()` 之間有 race**。
Link 在 check 時有 energy，但 link manager 在 withdraw 前 transfer 走了。
代碼無論 withdraw 成功與否都 `return`，upgrader 永遠不 fall through 到
container / spawn / storage。

### 影響
- 兩隻 upgrader 不做任何 upgrade work
- Controller 仍靠 haulers 灌 controller buffer 前進（69.2%），但效率打折
- upgradeRate 從 61.9 跌至 42.5

## 改動：upgrader link withdraw fallthrough

### 改動
`role.upgrader.js` link withdraw：`return` 只在 `ERR_NOT_IN_RANGE`（移動中）
或實際取得能量（`getUsedCapacity > 0`）時呼叫。Link 被 drain 導致 withdraw
失敗時 fall through 到 controller container / spawn-ext / storage。

```diff
-      return;  // always return — even when withdraw fails
+      if (linkResult === ERR_NOT_IN_RANGE) { ... return; }
+      if (creep.store.getUsedCapacity(RESOURCE_ENERGY) > 0) { return; }
+      // fall through — link was drained between check and withdraw
```

### 影響
- W49N25 upgraders 即時恢復 upgrade work
- upgradeRate 預期回升至 60+
- 不影響正常 link→upgrader flow（link 有 energy 時行為不變）
